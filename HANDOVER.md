## 1. What the app is
"Clean My City" is a free, public, no-login web app for Rawalpindi, Pakistan. Anyone can mark a waste site on a map, choose a waste type, write a description, optionally pick a locality and add a photo. Reports are public, shown on a map, in a "Recent reports" grid and on a leaderboard page (ranking areas). An admin (single shared password) can change report status, delete reports and download a CSV.
Long-term goal: automatically route each report to the responsible local authority, with escalation levels and scheduled email digests (see section 12).

## 6. Data model
Supabase table `reports`: id, lat, lng, type, description, locality, photo, status, created_at (id is a UUID generated by the server with crypto.randomUUID()).
TypeScript (types/index.ts):
- WasteType: household | construction | plastic | medical | other
- ReportStatus: reported | in_progress | resolved
- WasteReport: { id, lat, lng, type, description, locality?, photo?, status, createdAt }
- Also exported: WASTE_TYPES, TYPE_LABELS, TYPE_COLORS, STATUSES, STATUS_LABELS, STATUS_COLORS, RAWALPINDI_LOCALITIES (20 areas incl. "Other"; drives the dropdown and leaderboard grouping).
Photos: stored in public Supabase Storage bucket `report-photos` as `{reportId}.jpg`. For new reports the `photo` column holds the public URL. Older test reports still hold a base64 data-URL string in the column (the UI displays both).
Extra tables created for the future authority feature (RLS enabled, no public access, DUMMY data only, not yet used by the app): `authorities` (id, name, level 1-3, email, whatsapp, parent_id, active, created_at) and `locality_routing` (locality, authority_id). Dummy emails use example.com.

## 7. Architecture rule
Browser pages never talk to Supabase directly. Flow: page -> /api route -> lib/reports.ts (and lib/photoStorage.ts) -> Supabase using the service role key. `lib/supabaseClient.ts` must only be imported by server code.

## 8. API routes
- GET /api/reports: returns { reports } newest first, no-store. On database failure returns 503 { error }.
- POST /api/reports: validates lat/lng numbers, type in WASTE_TYPES, description required (trimmed, max 500 chars), locality optional string (max 100), photo optional string max 3,000,000 chars. If a photo is sent, `uploadReportPhoto` checks it is a data:image/jpeg;base64 string, decodes it, requires a real JPEG signature and max 2 MB, uploads it, and the public URL is saved. If saving the row then fails, the uploaded photo is deleted again. Returns 201 { report }. Validation errors 400, storage/database failures 503 with friendly messages.
- PATCH /api/reports/[id]: admin only; body { status } validated against STATUSES.
- DELETE /api/reports/[id]: admin only; deletes the row (returns 404 if missing), then deletes the photo file if the photo is a storage URL (old base64 values are skipped).
- GET /api/reports/export: admin only; returns CSV with a UTF-8 BOM. Columns: Date reported, Status, Waste type, Description, Locality, Latitude, Longitude, Google Maps link, View in Clean My City, Photo link ("Old format (no link)" for old base64 photos).
- GET /api/health: reads one row id; returns {"ok":true} or 503 {"ok":false}.
Admin check (helper `isAdmin`): request header `x-admin-key` must equal ADMIN_PASSWORD; if ADMIN_PASSWORD is unset every request is rejected. No rate limiting.

## 9. lib/reports.ts functions
getReportsOrThrow() (throws on error), getReports() (swallows errors and returns [] — kept for other callers such as the leaderboard), addReport(report), updateReportStatus(id, status), deleteReport(id) -> { deleted, photo }.

## 10. Frontend behaviour
Homepage (app/page.tsx): shows a welcome modal once per session (sessionStorage), hero, stats strip, the Leaflet map, a report panel that opens when the map is clicked or "Use my current location" is used, a "Recent reports" grid, leaderboard teaser, about section and footer. Photos are resized in the browser (max 1280 px, JPEG quality 0.7) and sent as a data URL. `?report=<id>` deep-links and flies the map to that report. If /api/reports fails, a red banner with a "Try again" button appears and stats show "—".
Admin (app/admin/page.tsx): password is held only in React state (lost on refresh). Unlock calls the export route to verify the password (401 = incorrect, other = database unavailable), loads the report list, and only then opens the admin screen. Each report has a status dropdown and a red Delete button with a confirm dialog; there is a Download CSV button.

## 11. Automation (GitHub Actions)
- keep-alive.yml: daily 06:00 UTC, curls /api/health. Prevents Supabase free-plan inactivity pausing; a failed run emails the owner.
- backup.yml: Mondays 03:00 UTC, downloads the CSV using the ADMIN_PASSWORD secret and stores it as artifact `reports-backup` for 90 days. Text data and photo links only; photo files themselves are not backed up (export the table from the Supabase dashboard occasionally).
Both can be run manually from the Actions tab.

## 12. Planned feature: authority routing and escalation (not built)
Idea: auto-assign each report to an authority from its coordinates, then escalate by age.
- Level 1 local (Rawal Municipal Town, Potohar Municipal Town, Tehsil Council Saddar, Tehsil Council Cantt, municipal committees, and the cantonment boards, which are separate from the city), Level 2 waste operator, Level 3 district (Deputy Commissioner). Each authority points to its parent via parent_id.
- Rawalpindi 2026 delimitation (reported 19 Aug 2026): Rawal Town 41 union councils, Potohar Town 33, Tehsil Saddar 22, Tehsil Cantt 29; four cantonment boards (Rawalpindi, Chaklala, Wah, Taxila). Verify before relying on it.
- Plan: store zone polygons (GeoJSON) in a `zones` table tagged with authority and priority (smaller/more specific zone wins), add `authority_id` to reports, assign on POST with a point-in-polygon check, fall back to locality_routing, else "Unassigned". Boundaries must be data, not code, so they can be swapped later. The only free national boundary file found (HDX, 2017) is outdated (82 old union councils vs 125 now), so start with roughly traced main zones (e.g. geojson.io) and replace with official maps later.
- Emails: start with a Gmail account (app password) for testing; scheduled digests ("open sites in your area, oldest first" with map links and photo URLs); owner reviews/approves reports before any email reaches a real official; one-click "acknowledged" link; WhatsApp only as click-to-chat links (automatic WhatsApp needs a paid API). Keep a notification log.

## 13. Known risks and ideas
- /api/reports returns every row including any old base64 photos; Vercel function responses are limited (about 4.5 MB, verify) so the site could fail as data grows. No pagination yet. Old test reports should be deleted.
- No rate limiting on POST or on admin password attempts; admin is one shared password.
- Row Level Security on the `reports` table has not been confirmed.
- Other ideas: pagination, admin filters/search, a "hidden" status (would need every list page to filter it), Cloudflare Turnstile, IP rate limiting.
